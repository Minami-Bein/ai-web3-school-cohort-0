▸ 账户类型概览
🔑
EOA
External Owned Account
Metamask 创建的账户，由私钥完全控制
私钥 = 资产所有权，无任何中间层
单点故障：私钥丢 = 资产永久丢失
无法设置限额、无法恢复、无法多人共管
🤖
智能账户
Smart Account / ERC-4337
合约代码控制账户，可编程权限规则
可设支出限额、社交恢复、时间锁
第三方 Paymaster 可代付 gas
AI Agent 钱包的最佳选择：有权做事，但不等于完全控制
🔐
多签账户
Multi-signature / Safe
N 个人持私钥，X 人签名才可执行交易
典型配置：2/3（3人中需2人确认）
单人被黑不会直接损失，需多人合谋
企业合规、DAO 金库首选：分布式信任

▸ 主要风险点
EOA 风险
单点故障
私钥泄露 = 资产永久丢失，无法冻结、无法撤回、无法申诉
无权限分层
无法设支出限额，无法区分"日常小额"和"大额转账"，要么全有要么全无
无法恢复
助记词丢失 = 资产永远无法找回，没有任何社交恢复选项
智能账户风险
合约漏洞
合约逻辑是安全根基，有漏洞则所有保护机制形同虚设，上链后无法修改
监护人风险
社交恢复依赖监护人，监护人合谋可夺走账户控制权
AI Agent 误用
Agent 若获得无限制授权，可自主转走全部资产——必须用限额和 Guardrails 约束
多签账户风险
门槛设置过低
1/2 多签几乎无保护意义，1人即可控制；建议至少 2/3 或更高
成员变更风险
旧成员退出时若未及时更新配置，恶意成员可趁机夺权
无自动化
无法预设自动执行策略，紧急操作需要等待多签确认，响应速度慢

▸ 5 句话总结
Flow Summary
解决什么问题
明确"谁能发起交易、谁能批准、谁承担风险"——三者答案在不同账户类型下完全不同，选错会让 AI Agent 的 Web3 操作要么风险失控，要么根本无法执行。
AI / Agent 辅助的步骤
AI 负责分析意图（读取链上数据、评估 Gas、生成操作建议），以及在智能账户的自动化模块中按预设策略触发交易——但都受制于账户类型设定的权限边界。
必须人工确认的步骤
签名授权（approve）和交易广播（broadcast）必须在用户钱包内完成；多签场景需达到门槛人数分别确认。AI 无法替代这一步，否则 Agent 持有私钥本身就是最大风险。
如何验证最终结果
交易广播后，用 tx hash 在区块浏览器（Etherscan / Sepolia Etherscan）核对状态（success / fail）、事件日志和 Gas 消耗，再对比操作前后钱包余额，确认结果与原始意图一致。
主要风险点
EOA 单点故障（私钥丢 = 资产全丢）、智能账户合约漏洞、多签门槛设置过低（1/2 几乎无保护），以及三者的共同风险——用户对 approve 授权范围理解不足被恶意合约滥用。
