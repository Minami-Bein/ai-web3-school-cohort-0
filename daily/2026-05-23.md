## 📚 学习内容

### Web3 安全底线

**常见风险清单：**

**1. 私钥泄露（Private Key Leak）**
Agent 如果存储用户私钥，一旦被攻破，资产全部可被转走。
→ AI Agent 绝不能存储原始私钥，应用智能钱包/会话密钥。

**2. 钓鱼攻击（Phishing）**
伪造的 dApp、签名请求、恶意链接。用户或 Agent 被诱导签署恶意交易。
→ Agent 应显示清晰的操作摘要，让用户确认意图。

**3. 错误地址（Wrong Address）**
复制粘贴错误、转账到错误地址。链上交易不可逆。
→ Agent 应校验地址格式、历史记录，提供地址白名单功能。

**4. 恶意授权（Malicious Approval）**
用户授权了恶意合约无限动用资产（如 ERC20 approve）。
→ Agent 应告知授权范围和额度，定期提醒用户撤销不必要授权。

**5. 合约漏洞（Contract Vulnerability）**
调用未审计合约可能导致资金损失。Flash loan、reentrancy 等经典攻击。
→ Agent 应只推荐经过审计的合约，或在操作前提示风险。

**6. RPC / 数据源不可信**
使用恶意的 RPC 节点可能返回假数据（假余额、假状态）。
→ Agent 应使用多个可信数据源交叉验证，避免单一来源。

**7. Prompt Injection（提示词注入）**
用户输入中嵌入恶意指令，让 Agent 执行非预期操作。
→ Agent 应有指令边界，外部输入不能覆盖核心指令。

**8. 无限 mint / 超额铸造**
合约漏洞被利用导致超发代币。
→ Agent 应设置操作额度上限，监控异常铸造行为。

### AI Agent × Web3 安全原则

| 风险 | Agent 应对方式 |
|------|---------------|
| 私钥泄露 | 用智能钱包/会话密钥，不存明文私钥 |
| 钓鱼攻击 | 展示操作摘要，用户明确确认 |
| 错误地址 | 格式校验 + 历史记录匹配 |
| 恶意授权 | 授权额度限制 + 定期撤销提醒 |
| 合约漏洞 | 只用审计合约，风险提示 |
| 数据不可信 | 多数据源交叉验证 |
| Prompt injection | 指令边界，外部输入不能覆盖核心指令 |

## 💭 思考与收获
- AI Agent 做 Web3 操作的核心安全边界：只读可自动，写入必须用户确认
- 私钥管理是最高风险点，智能钱包（smart wallet）是解决方案方向
- 很多 Web3 安全问题和 AI 安全问题是交叉的——两个领域都要防
