# Handbook Feedback

学习过程中发现的问题、卡点、错别字、概念不清或建议，整理在这里并回流到 Handbook 改进。

## 目标

- 每条 feedback 可开源、可索引、可复盘
- 回流给 Handbook 作者，帮助平台迭代
- 同时作为个人学习的问题记录

## Feedback 类型

| 类型 | 说明 |
|------|------|
| 错别字 | 文字、标点错误 |
| 概念不清 | 术语未解释或解释模糊 |
| 资料过期 | 链接失效、内容过时 |
| 结构建议 | 章节顺序、层级、重复 |
| 内容补充 | 缺少的关键背景知识 |
| 其他 | 以上之外的建议 |

## 流程：每日学习时即时记录

```
每日学习
  ↓
遇到卡点 / 发现问题
  ↓
在 daily/YYYY-MM-DD.md 的 [❓ 待解决] 栏目记录
  ↓
当日或次日判断：这是 Handbook 本身的问题吗？
  ↓ 是
  → 在 handbook-feedback/ 创建文件
  → 同时更新 daily note 中的相关记录
  ↓ 否
  → 记录到 daily note 的 [❓ 待解决] 留给之后解决
```

## 文件命名

```
handbook-feedback/YYYY-MM-DD-issue-title.md
```

例如：
- `2026-05-23-密码学章节-ECDSA描述缺少图示.md`
- `2026-05-24-智能合约-gas计算示例不完整.md`

## 每条 Feedback 包含

- **Handbook 页面链接**（锚点链接）
- **问题描述**（清晰、具体）
- **建议改法**（具体可行）
- **来源**（个人学习心得 / 群聊讨论）
- **严重程度**（🟡轻微 / 🟠中等 / 🔴严重）

使用 `feedback-template.md` 模板创建。

## 提交检查清单

每次 commit 前确认：
- [ ] 每条 feedback 有页面链接
- [ ] 问题描述清晰、可操作
- [ ] 严重程度已标注
- [ ] daily note 中有对应的待解决问题引用
